# Веб-панель Supabase для GitHub Pages

Статическое приложение показывает данные таблиц бота из Supabase. Оно не содержит секретного ключа и не запускает Node.js на GitHub Pages.

## Установка

Скопируйте содержимое папки `sait` в корень репозитория `atomyweb` и опубликуйте его через GitHub Pages. Публичный сайт должен включать `index.html`, `app.js`, `styles.css` и `supabase-setup.sql`.

В `app.js` уже указаны URL проекта Supabase и publishable key. Такой ключ предназначен для клиентских приложений. Доступ к данным защищает Supabase Auth вместе с RLS-политиками; сам по себе publishable key не должен давать доступ к строкам таблиц.

## Настройка Supabase

1. Создайте или перенесите в Supabase таблицы `users`, `admins`, `support_requests`, `bot_settings` и `user_topics` с колонками, указанными в `app.js`.
2. Откройте Supabase Dashboard → SQL Editor и выполните `supabase-setup.sql`.
3. В Authentication создайте учетную запись Email/Password для каждого администратора панели. Не включайте публичную регистрацию, если она не нужна.
4. Скопируйте UUID учетной записи из Authentication → Users и выполните в SQL Editor:

   ```sql
   insert into public.dashboard_access (user_id)
   values ('UUID_ПОЛЬЗОВАТЕЛЯ');
   ```

5. Откройте сайт GitHub Pages и войдите по этой учетной записи.

Пользователь панели получает только `SELECT` к перечисленным таблицам и только пока его UUID есть в `dashboard_access`. Не добавляйте политику чтения для `anon`/всех пользователей: таблицы содержат данные Telegram-пользователей.

## Где берутся данные

Панель читает данные из таблиц Supabase. Она не читает локальный `bot.sqlite3`. Если бот сейчас сохраняет данные только в SQLite, ему или отдельному доверенному серверному процессу нужно дополнительно записывать их в Supabase. Это нельзя безопасно делать из страницы GitHub Pages с использованием secret key.

`npm install @supabase/server` относится к серверному окружению и сам по себе не подключает GitHub Pages к базе. Для статической страницы клиент Supabase загружается как ES-модуль; secret key в браузер не передается.

## Важно: ключи

Никогда не добавляйте `SUPABASE_SECRET_KEY` в JavaScript, HTML, переменные GitHub Pages или публичный репозиторий. Secret key дает расширенные права и обходит RLS. Если он уже публиковался или был отправлен в общий чат/репозиторий, отзовите его и выпустите новый в настройках Supabase. Удаление строки из файла не отзывает уже скомпрометированный ключ.
